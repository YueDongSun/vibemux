  pre-alpha, **read-only scope**). A chat is a daemon-owned session with its
  own state machine, its own durable metadata, and protected private bodies
  for titles, prompts, and assistant output. **Control v11** adds one
  persistent-chat operation carrying a fixed request enum (`list`, `open`,
  `lookup_open`, `status`, `submission`, `send`, `cancel`, `turns`, `title`,

  **Store schema 10** adds the chat metadata tables. A chat is a separate
  aggregate from `Task`/`Run`, and each admitted turn carries its own
  canonical `TaskId` and `RunId` plus the Git HEAD observed at admission.
  Opening a chat requires an explicit private-storage consent, which is
  separate from the one-turn Ask consent; project registration is an identity
  boundary and carries no consent grant of its own. Daemon
  startup, listing, and status are read-only and launch no vendor process
  and create no private storage. Claude resumes by its exact stored vendor
  session id and Codex by its exact stored thread id; a resume is refused
  when the route profile or workspace resource key changed. Private bodies

  an opaque blob id, digest, and byte count rather than a path. Reads are
  bounded to 8,192-byte chunks with revision-bound live cursors, and a
  repeated send after a restart or a purge returns the original receipt
  instead of a second effect. A close reserves its operation before it stops

  one-shot Ask request ids in both directions so neither namespace can be
  mistaken for the other. The existing one-shot Ask path is unchanged.

  leaf after its descriptor and writer lock are gone, but only when the
  leaf is an empty real directory at its canonical path. Links, junctions,

  the leaf for diagnosis and recovery. Existing leaves are not pruned.
  `vibemuxctl daemon stop` now returns only after the daemon process has
  exited. Leaf ownership is bound to one daemon generation by the
  project-local compatibility lock. A start acquires that lock before it
  creates the leaf, and a clean shutdown releases the leaf before it removes
  the lock, and only while the lock is still its own. A start that runs

  `writer_lock_held`. It never has the leaf it uses removed under it. A
