# Protocol boundaries

- **Internal Event**: append-only canonical SQLite model, independent of terminal output.
- **Local control IPC**: `vibemuxd::control` implements the private pre-alpha v5 authenticated Windows named-pipe/POSIX UDS transport: v1 `health`/`shutdown`, v2 read-only `plugin_status`, v3 harness registry operations, v4 frontend queries and terminal observation, and v5 harness dispatch. Each operation keeps its minimum version, and the daemon accepts v1–v5 requests. On Windows the descriptor/lock lives in a protected per-user hashed runtime and the pipe rejects remote clients; on POSIX the descriptor is `0600`. There is no TCP fallback. `vibemuxctl` covers the standalone daemon lifecycle, explicit stale metadata recovery, harness listing and switching, and harness dispatch; it does not directly touch SQLite and never exposes token/endpoint path.
- **PTY**: provides interactive input/output only and never infers completion/approval.
- **ACP/MCP**: no gateway exists. ACP v1 over stdio is used only for initialize-only harness dispatch probes of OpenCode, Copilot, and Grok (ADR 029); ACP prompt execution and MCP remain unimplemented.
- **Harness dispatch**: `vibemuxd` drives Codex `exec --json`/`app-server` and Claude stream-json one-shot turns through pure `vibemux_harness::dispatch` state machines, launches the vendor CLI through the first-party trampoline inside a contained process tree, and records a content-free Task/Run outcome (store schema 4). It is opt-in through `.vibemux/harness_dispatch.json`, runs at most one dispatch per project with read-only protocol profiles that are not an OS sandbox, and returns raw vendor records only from the `harness_dispatch_output` operation. Live vendor CLIs are not yet validated. See [ADR 029](adr/029_daemon_harness_dispatch.md).
- **Plugin stdio**: `vibemux_plugin_protocol` implements the private pre-alpha Protobuf v1 schema, fixed-ceiling framing, manifest/negotiation, and session lifecycle; the wire crate itself has no process dependency, and the SDK and real plugins are still unimplemented.
- **Plugin supervisor**: `vibemux_plugin_supervisor` has been validated with real Windows/Linux mock children for stdout-only framing, independent bounded stderr metadata, bounded queues, deadline/heartbeat/cancel/drain/shutdown/crash; M4.2 adds a daemon-owned registry, bounded restart budgets and quarantine with native Windows mock evidence. SDKs and real vendor plugins remain absent. See [registry protocol](plugin_registry_protocol.md) for ephemeral status, startup configuration and shutdown limits.
- **A2A**: the original information-share API remains available. The new authenticated local task gateway implements HTTP+JSON/JSONRPC/gRPC through official SDK boundaries, bounded task/artifact/status/cancel/subscription mapping, and a daemon-owned supervisor backend with atomic canonical bindings and independent verifier gates. Remote bind/TLS, push, complete message history and full official ITK are not claimed. See [stateful protocol](a2a_supervisor_protocol.md) and [conformance evidence](a2a_conformance_validation.md).
- **Git artifact**: worktree, diff, and commit are auditable artifacts; merge is never automatic.
