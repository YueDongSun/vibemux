# Algorithms and invariants

State transitions are driven by the explicit transition table in `models.py`; a Run may enter `succeeded` only with structured-adapter, verifier, or user authority. State writes and event appends occur in one SQLite transaction. Each Run persists the `base_commit` captured at creation. Diff compares the working tree with that commit and adds patches for untracked files, covering committed, staged, unstaged, and untracked changes. Git and terminal commands use one shell-free `CommandRunner`; tmux keeps `agent_host` and its target as separate argv entries. If an external Git or terminal side effect fails, spawn compensation stops only a terminal whose identity was returned and executes only an immutable cleanup plan that remains safe after revalidation; the branch is preserved. Reconciliation validates worktree and terminal inventory, marking a running Run as `stale` when resources are missing or ownership mismatches while treating an ordinary dirty worktree as valid. Path checks use `commonpath` and `normcase`, never string `startswith`; cleanup is dry-run by default and refuses dirty, unknown, main, or out-of-root worktrees.
